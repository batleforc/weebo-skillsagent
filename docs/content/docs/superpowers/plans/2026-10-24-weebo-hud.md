> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code mod, `weebo-hud`. It draws a powerline band (session facts plus free RAM, CPU and disk) and a French resume pane that Claude fills through a tool. It ships from this repo's marketplace and installs through wska.

**Architecture:** One plugin folder, `mods/weebo-hud/`. The pure logic lives in two files, and the tests import them directly: `hooks/metrics.ts` (parsers) and `hooks/format.ts` (segments, levels, reset times). `hooks/register.tsx` holds all the engine wiring: timers, `$.state`, `$.store`, the tool, the command and the two render hooks. `hooks/notes.ts` holds the store helpers.

**Tech Stack:** The Claude Code mod API (build 2.1.309, EARLY ACCESS). TypeScript/TSX with `h` as the JSX factory. `claude-code/testing`, `claude plugin test` / `validate`, `tsc` through npx, Taskfile and wska.

**Spec:** `docs/content/docs/superpowers/specs/2026-10-24-weebo-hud-design.md`. Executors read it first: colors, thresholds and copy are taken from it.

## Global Constraints

- The API reference is the `plugin-authoring` skill (load it). The authoritative types are written to `mods/weebo-hud/.claude-plugin/types/` once the engine has loaded the mod. Check every `$` signature there, not in this plan.
- No Node and no DOM: everything goes through `$`. Dynamic `import()` is not allowed. Sibling static imports are allowed.
- `$.state` refs use literal `plugin: 'weebo-hud'` and literal keys. No `$.state` writes inside a render hook.
- UI text is in French and taken word for word from the spec (`libre`, `Objectif`, `Plan`, `Notes`, `En attente`, French day names).
- Colors are hex: blue `#005fd7`, violet `#875fff`, green `#00af00`, orange `#d7af00`, red `#d70000`, text `#eeeeee`. The separator is U+E0B0.
- Commits: Claude never commits. Each "Commit" step means: write the message to `<scratchpad>/commit-msg.txt` in Conventional Commits form, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, then give the user `git add <files> && git commit -s -S -F <path>`.
- Every new Taskfile task has a `desc`. Task files go in `.tasks/`, never `.task/`.
- Run `graphify update .` after code changes.

## Review Focus

1. **A cgroup v2 pod with `memory.max` set** (Che): RAM must show the pod's limit, not the host's. Test: `parseCgroupMemory` with a real limit (Task 2).
2. **A `rateLimits` with only one window, or none** (API key, long-lived token): each segment shows `—` on its own, and the other never shifts. Test in Task 3.
3. **`/proc` or `df` unreadable or failing** (sandbox refusal, missing `df`): the band still draws, with `—` for that metric. Test: `sampleMetrics` with a failing reader (Task 4).
4. **`--resume` of a session that has notes**: the pane comes back with its content. Test: seed the store, then `session.start`, then mount the pane (Task 5).
5. **A notes value from an older shape in the store** (missing `todos`, or a non-object): it must not crash the pane. Test: `loadNotes` normalises it (Task 5).

### Task 2: Metric parsers

**Interfaces:**
- Produces (types, all byte figures in bytes):
  - `Metrics = { ram?: { free: number; total: number }; cpu?: number; disks: { fs: string; avail: number; size: number }[] }`
  - `CpuTick = { busy: number; total: number }`, in the same unit as its source: µs for cgroup, jiffies for `/proc/stat`.
- Produces (functions):
  - `parseMeminfo(text: string): { free: number; total: number } | undefined`: `MemAvailable` and `MemTotal`, in kB × 1024.
  - `parseCgroupMemory(max: string, current: string): { free: number; total: number } | undefined`: undefined when `max.trim() === 'max'`.
  - `parseCpuMax(text: string): number | undefined`: quota/period in cores, undefined for `max …`.
  - `parseCgroupCpuStat(text: string): number`: `usage_usec`.
  - `parseProcStat(text: string): CpuTick`: from the aggregate `cpu ` line. busy = total − idle − iowait.
  - `cpuPercent(prev: CpuTick, cur: CpuTick): number | undefined`: clamped to 0–100, one decimal. Undefined when Δtotal ≤ 0.
  - `parseDf(text: string): { fs: string; avail: number; size: number }[]`: reads `df -kP` output, skips the header, deduplicates by the first column, kB × 1024.

## Revision (2026-10-24, after the live test): status line in wska, mod keeps the pane

The live test showed the band drawn above the prompt. The user wants the classic `statusLine` back under the prompt, rendered as ANSI, with no `jq` anywhere. Decision: wska carries both the status line and its install. The mod keeps only the resume pane, `set_status` and `/etat`. The original Task 7 (manual retirement with `jq`) is replaced by Tasks 7–9 below.

Facts (from the official statusline docs):
- The stdin JSON carries:
  - `cwd`, `workspace.current_dir` and `model.display_name`;
  - `context_window.used_percentage`, which can be null;
  - `rate_limits.five_hour` and `rate_limits.seven_day`, each `{ used_percentage, resets_at }` with `resets_at` in epoch seconds. Each window may be absent.
- `statusLine.refreshInterval` is in seconds, minimum 1. ANSI is supported. A running script is cancelled when a new update fires.
- A plugin cannot set the main `statusLine`: it must go in the user's settings.
